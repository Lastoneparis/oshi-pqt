# Contributing to OSHI

Thank you for helping make the web’s post-quantum transition safer.

## Before opening a change

1. Search existing issues and discussions.
2. Keep proposals narrowly scoped and explain the interoperability impact.
3. Never submit new cryptographic primitives or ad-hoc wire formats as production solutions.
4. Add test vectors or reproducible captures for implementation-facing changes.

## Good first contributions

- Compare the profile to current IETF TLS work.
- Improve the threat model or deployment guidance.
- Build a reproducible test harness using an audited TLS stack.
- Report unclear language or missing operational safeguards.

## Pull requests

Use clear commits, explain the security rationale, and update the relevant document. Changes that affect cryptography, certificates, or negotiation require independent review before adoption.
